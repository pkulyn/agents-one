# Agents One 手机端与 macOS 桌面端开发 PRD

状态：产品方向确认，待按阶段实施。更新日期：2026-10-03。

## 1. 目标与顺序

将 Agents One 从 Windows 桌面工作空间扩展到手机和 Mac，保持“对话优先、项目是对话/任务容器、Runtime 保留原生能力”的产品契约。实施顺序为：**公共移动契约 → Android → iOS → HarmonyOS 5 及以上原生应用 → macOS 桌面版**。鸿蒙最小技术探针在 Android 阶段开始时完成，以便提前发现工具链和插件缺口；若真实用户需求优先级改变，平台顺序可单独决策，不重写共同协议。

本 PRD 是后续智能体的实施入口，不代表任何平台已经发布。源码公开与安装包/应用商店验收是不同闸门。当前 Windows Alpha 制品继续遵循 [RC1 清单](./AGENTS_ONE_RC1_RELEASE_CHECKLIST.md)，远程 Hermes 多轮/重启续接继续列为实验性已知问题。

## 2. 当前基线与不可破坏的边界

- 桌面端以 Electron 本机进程运行 Pi、Codex、Claude Code 等本地 CLI；远程 Runtime 走 [Gateway v1](./AGENTS_ONE_REMOTE_GATEWAY_V1.md) 和 [Connect](./AGENTS_ONE_CONNECT_DEVELOPMENT_PLAN_20260821.md)。手机不在本机启动桌面 CLI，也不接收桌面进程的任意命令转发。
- 桌面项目、会话和用户配置目前主要持久化在本机。Gateway 的 Run/会话证据不能被当作全部桌面对话历史；移动端必须显式设计可同步范围和存储责任，不静默上传现有私人历史。
- Gateway Token 与 Connector 设备凭据、Workspace Grant 分离。现有 Connect 桌面安装身份不能复制给手机；移动端需要独立的设备身份、最小 scope、撤销和轮换。
- 现有 Runtime ID、头像、名称、项目归属、对话和备份格式保持稳定。任何跨端同步实现须先按 [变更安全守则](./AGENTS_ONE_CHANGE_SAFETY_PROTOCOL.md)记录数据、消费者、回退与回归范围。
- 公共源码仍可能含实验性 Runtime；移动端只对经过相应端到端门禁的 Runtime 开放功能，不用普通文本回复冒充 Artifact、完成事件或已验证的上下文续接。

## 3. 手机端 v1 用户旅程

### 3.1 首发范围

用户安装手机应用，独立配对自己的设备，选择一个被授权的远程 Runtime，创建对话并看到流式回复、工具进度、失败、离线和取消状态。关闭应用后重新打开，可从服务端恢复该移动对话的消息和最后事件游标。用户可撤销本手机的访问，而不影响其他设备的凭据。

首发包含：设备配对/撤销、授权 Runtime 列表与能力、移动新对话及继续对话、SSE/游标恢复、Run 终态、有限的 Artifact 元数据与安全下载、基础搜索/列表。附件上传、计划任务编辑、多智能体协作控制、工作区写权限和历史桌面对话导入在后续阶段单独验收；首版界面不得出现尚不能兑现的按钮。

手机端只能使用明确授权的远程 Host/Gateway 能力。桌面本地 CLI 若要在手机发起，必须先由用户在受控设备上部署、配对并验收相应远程 Adapter；手机不直接读取电脑文件、浏览器会话或本地密钥。

### 3.2 跨设备数据契约

公共协议须有版本号、稳定的 `runtimeId`/`conversationId`、每轮 `turnId`、幂等提交键和可恢复的事件游标。用户消息、助手消息、工具/推理摘要、失败、取消及 Artifact 元数据应有不同类型；客户端按服务端序号对账，不能仅以时间戳排序。服务端必须在回报终态前持久化本轮的可恢复证据；重复提交和重连不能产生第二个 Run 或第二条消息。

移动 v1 只同步**配对后由移动端创建或用户明确加入同步的远程对话**。旧桌面历史、项目文件和本机 Web Provider 会话默认留在本机。后续若支持桌面历史同步，先定义用户选择、端到端数据清单、删除/撤销、冲突处理、备份和回退，再提交迁移 PR。

### 3.3 身份、隐私和离线

每台手机有独立、可撤销的设备身份；配对证明短期有效，长期凭据使用平台受保护存储，服务端按设备及 Runtime 授权。Token、完整提示词、附件正文和绝对路径不得进入 URL、日志、通知预览或诊断导出。Workspace Grant 继续逐次、短时授权，不因配对自动开放。离线可看已缓存的有限历史，但新运行必须明确显示未提交或失败，不在恢复联网时暗中重放可能修改文件的请求。

首发的推送通知仅传递无敏感内容的状态和不透明标识；通知能力、后台行为和数据保留策略需分别通过平台验收。设备遗失后的撤销必须拒绝新请求及新事件流；已下载到设备的内容按本地数据清理策略处理。

## 5. 共同验收矩阵

每个平台使用同一脱敏测试 Host 和相同随机标记验证：新对话、连续四轮回忆、取消后下一轮、应用/Host 重启后续接、新旧设备隔离、网络中断与游标重放、明确的 401/403/409/429/503、重复提交、Artifact 下载权限与撤销。失败场景须核对服务端 Run 终态和客户端展示，不能只凭界面截图判定成功。远程 Hermes 在其 Connector 原生续接问题关闭前不得作为全部平台通过的替代证据。

每个平台的发布对象固定 commit SHA、依赖锁文件、产物哈希和测试报告。源码/PR CI 通过只证明代码候选；安装包或商店包另需目标 OS 的普通用户安装、真实设备和分发验收。未经验证的平台在 README、商店描述和下载页中标为未发布。

## 7. 对外路线

先公开经审计的 MIT Alpha 开发源码，标明当前仅有 Windows 桌面候选和远程 Hermes 限制；不以移动 PRD 宣称已有手机应用。随后按 M0、M1、M2、M3、D1 各自的验收结果决定测试分发和正式发布，互不借用另一平台的通过记录。

# 远程智能体安全参与本地项目

## 目标

让远程 Hermes、OpenClaw 等智能体能够参与办公电脑上的项目，而不是把办公电脑暴露为一台可被远程任意访问的文件服务器。

基本原则：

- 不开放 SMB、RDP、HTTP 文件服务或任意入站端口。
- 远程端不获得 Windows 本地路径、Windows 用户凭据、共享盘凭据或任意 Shell 权限。
- 仅由 Agents One 主进程在用户明确选定的项目根目录内执行受控操作。
- 所有访问均按任务、角色、最小权限和短时令牌约束，并保留本地审计记录。
- 删除操作必须由用户逐次确认；不得用“完全访问”绕过此规则。

## 阶段一：只读证据包（已实现）

适用对象：远程规划、测试、复核、验收角色。

1. Agents One 在本机生成有限、只读的项目快照。
2. 快照只包含相对路径、受限数量的文本文件和大小上限内的内容；每个入包文件均附带平台计算的入包字节数与 SHA-256 清单。
3. 自动排除 `.git`、依赖目录、构建目录、符号链接以及 `.env`、密钥、证书、凭据、令牌等敏感文件。
4. OpenClaw 通过其 Bridge Artifact API 接收该快照；Hermes 通过已有的受控文本附件通道接收。
5. 远程角色提示词不包含本机项目绝对路径；交接材料和验收证据中的 Windows 路径会替换为 `<本地项目>` 或 `<本地路径>`。

阶段一不允许远程角色写入本机文件。远程角色可以基于证据包提出建议、编写补丁、测试方案或验收结论，但不能声称已直接读取本机目录。

## 阶段二：受控远程写入（本机侧已完成，待远程 Bridge 联调）

采用**办公电脑主动出站连接**，而不是让远程服务器反向连接办公电脑。

### 连接模型

1. Agents One 主进程向已认证的远程 Bridge 建立 TLS 长连接或短轮询通道。
2. 用户在某个任务中授权某个远程角色后，主进程创建短生命周期 `workspaceGrant`。
3. Grant 绑定任务、角色、项目根目录、权限范围、过期时间和一次性令牌。
4. Bridge 只能向该出站通道提交结构化文件操作请求；不能探测办公电脑网络、端口、用户目录或其他项目。

### 允许的操作

| 操作             | 权限           | 执行条件                                                   |
| ---------------- | -------------- | ---------------------------------------------------------- |
| `list` / `read`  | 只读或完全访问 | 路径必须位于已授权项目根目录内                             |
| `write` / `move` | 完全访问       | 本地验证相对路径、文件大小、前置哈希；写入后生成差异和哈希 |
| `delete`         | 完全访问       | 每一次请求都显示本地确认框，确认后才执行                   |

明确禁止：任意 Shell、进程启动、注册表、网络扫描、访问项目根目录外路径、符号链接跳转、批量删除和未经确认的覆盖。

### 请求与审计

每次请求至少绑定 `taskId`、`runtimeId`、`workspaceGrant`、操作类型、相对路径和预期 SHA-256。主进程返回结果、写前/写后哈希、差异摘要、时间和拒绝原因；这些记录会进入协作时间线和真实产物清单。

本地路径不会回传给远程端。远程端只使用项目内相对路径，例如 `src/app.ts`。

当前 v1 的本机执行器已经具备 `list/read/write/move/delete`、根目录约束、链接拒绝、冲突哈希和删除确认；完整的远程接口、请求格式和服务端审计要求见 [OUTBOUND_WORKSPACE_GATEWAY_BRIDGE_REQUIREMENTS.md](OUTBOUND_WORKSPACE_GATEWAY_BRIDGE_REQUIREMENTS.md)。首版刻意不支持 `patch`，以避免歧义补丁造成不可预期的文件改动；需要修改时由远端提交完整 UTF-8 文件内容并携带前置哈希。

## 阶段三：远程映射与外部工作区

对于已经有 VPN、Git worktree、受限共享目录或 NAS 工作区的环境，可使用“远程映射”。该选项不是自动授予办公电脑访问权限：

- 必须由远程智能体的 Bridge 先执行只读探测，并报告映射是否实际可达。
- 映射引用、Git 分支或共享目录权限由用户所在组织单独管理。
- 若探测失败，协作必须停在“等待人工处理”，可改派本地角色或回退到只读证据包。

## 协作规则

- 实施角色的交付必须包含真实文件/代码变更、来源、哈希和摘要；单纯大模型答复不属于产物。
- 测试和验收角色只能引用平台已记录的真实产物与证据。
- 远程只读角色可参与规划、测试和验收；需要修改本机项目时，先由用户授权阶段二，或改派本地实现角色。
- 任何超时、断连、权限不足或哈希冲突均阻断后续依赖阶段，等待重派、介入或取消。

## 验收清单

### 阶段一

- 远程 Hermes 和 OpenClaw 都能收到受限项目证据包。
- 证据包不含绝对本地路径、`.env`、密钥、符号链接目标或被忽略目录内容。
- 未选择项目时，远程只读证据角色无法启动。

### 阶段二

- 读取、创建、编辑、哈希冲突、超时、取消、断连重连均有可追溯结果。
- 路径穿越、符号链接、项目外路径、超限文件和无效令牌均被拒绝。
- 删除在用户确认前不产生磁盘变化。
- 远程端无法主动连接办公电脑，也无法获得本机绝对路径或凭据。

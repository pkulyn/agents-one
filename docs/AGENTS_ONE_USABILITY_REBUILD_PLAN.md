# Agents One 可用性重构计划

日期：2026-07-16  
状态：U0 至 U4 已完成；U5 进行中。  
前置成果：多 Runtime、任务控制面、项目控制面、Bridge 和本地持久化已可用。

## 1. 为什么需要单独重构

当前工程已经具备 Hermes、OpenClaw、Codex、Claude Code 的连接与任务执行基础，也已实现项目、任务、事件、产物和计划任务的数据模型。但界面仍主要继承自 Hermes Desktop：信息架构以单个远程 Hermes 为中心，旧模块入口分散，项目和任务功能的入口与日常对话割裂。因此，底层能力可用不等于客户端已经好用。

Multica 的“智能体是团队成员、项目是任务容器、看板展示状态、活动流显示执行过程”的产品模型适合作为参考；不复制其前端、后端或服务端代码。Agents One 继续使用 Electron 主进程、Runtime Adapter、远程 Bridge、工作树和本地数据层，不引入 Multica 的 Go 服务、PostgreSQL、Docker 或 daemon。

## 2. 重构目标

首屏只保留四个高频入口：**对话、项目、任务中心、智能体**。用户从任一入口都能在两步内完成以下事情：

- 选择一个智能体开始或继续对话；
- 将一次对话转为任务或关联到项目；
- 查看任务的当前阶段、实时过程、产物与验收；
- 为一个项目指定协调者、执行者、测试者和验收者；
- 管理已接入智能体的名称、图标、默认 Runtime 与健康状态。

不在首版主导航展示：发现、社区、钱包、旧 Profile/Persona、独立 Cron、旧 Kanban、供应商和网关等 Hermes Desktop 遗留入口。它们在确认仍有价值前隐藏，不删除底层兼容能力。

## 3. 信息架构

```text
Agents One
├─ 对话
│  ├─ 智能体选择器
│  ├─ 按智能体分组的会话
│  ├─ 统一消息与过程时间线
│  └─ 可隐藏的任务侧栏
├─ 项目
│  ├─ 项目总览
│  ├─ 工作项 / 看板
│  ├─ 团队与协调者
│  ├─ 资源与产物
│  └─ 项目活动
├─ 任务中心
│  ├─ 全部任务 / 与我有关 / 计划任务
│  ├─ 列表与看板
│  ├─ 任务详情抽屉
│  └─ 运行记录、验收和产物
└─ 智能体
   ├─ 智能体卡片与 Runtime 绑定
   ├─ 图标、名称、颜色、角色
   ├─ 健康探测与连接配置
   └─ 高级 Runtime 设置
```

## 4. 分轮实施

### U0：界面基线与数据兼容

1. 审计现有 Hermes Desktop 页面、路由、遗留入口和可复用组件。
2. 为新壳建立功能开关；旧页面保留为兼容回退，不迁移或删除用户数据。
3. 建立桌面截图基线：1440x900、1280x800、1024x768 三个尺寸。
4. 明确“页面验收”与“接口测试”是两项独立门槛。

验收：旧对话、任务、项目、Runtime 配置和缓存仍可打开；能一键回退到旧界面。

### U1：新的应用壳与主导航

1. 以 `对话 / 项目 / 任务中心 / 智能体` 重建左侧主导航，保留设置为低频入口。
2. 移除当前顶部多标签对内容区宽度的侵占；主内容采用稳定的三栏网格：左侧导航 248px，中间弹性主区最小 640px，右侧上下文栏 320px 且默认折叠。
3. 右侧栏只在对话、项目、任务详情有上下文时展开；小窗口自动叠为抽屉，绝不挤压输入框和消息区。
4. 全量中文化所有用户可见文本，统一中文状态、日期、错误和空状态。

验收：1024px 宽度下，左导航、消息区和输入区均保持完整可用；没有无功能入口出现在主导航。

### U2：对话工作台

1. 把 Hermes、Codex、OpenClaw、Claude Code 统一为同一个对话容器：相同的顶部身份条、消息气泡、过程事件、附件预览和底部编辑器。
2. 每条会话绑定一个 Agent ID；会话列表显示图标、智能体名称、标题、最后消息和时间，禁止同一远端会话重复入库。
3. 编辑器统一保留附件、项目目录、模型选择和网页预览；不存在能力的控件禁用并说明原因，不显示遗留“推理强度/快速模式”。
4. 对话右侧栏显示关联项目、任务、最新运行、产物和验收，支持“从本轮对话创建任务”。

验收：四类智能体可分别连续对话；同一轮请求只显示一次用户消息和一次最终答复；过程事件按 Runtime 实际能力呈现。

当前进展（2026-07-16）：

- Hermes 与本地/远程 Runtime 已共用身份条、可折叠会话任务侧栏与统一编辑器框架；
- 对话与 Task Center 已通过本地持久化关联，真实 Codex 对话已验证“创建任务、完成、刷新后恢复”；
- 对话侧栏已展示关联项目、当前运行、关联任务和产物摘要；底层 JSONL/网络重试日志不再混入用户摘要；
- 后续继续补齐附件/产物预览与四类 Runtime 的连续对话视觉回归。

### U3：项目与任务工作台

1. 项目页改为紧凑总览：目标、协调者、团队、任务进度、阻塞、最新产物和活动流。
2. 任务中心提供列表、看板和计划任务三个视图；详情使用右侧抽屉，不再跳到孤立页面。
3. 任务状态和运行状态分层展示，任务卡只显示与用户决策有关的信息；日志和原始事件默认折叠。
4. 计划任务迁移进任务中心，保留已有 Cron 数据、运行历史与手动触发。

验收：用户从项目总览能进入任务、对话和产物；从任一任务能查看输入、输出、运行日志和验收结论，无需在多个页面之间来回查找。

当前进展（2026-07-16）：

- 项目页在已有项目时默认展示总览与项目卡片，仅按需展开新建表单；中等窗口下自动将三栏详情调整为摘要全宽、任务和调度两栏；
- 任务中心已提供执行任务、定时任务、列表、看板和详情侧栏；运行日志保持折叠，输入、产物与验收信息集中在详情中；
- 任务列表正文已限制为三行摘要，完整输入保留在详情抽屉；远程对话降级提示只在对话页面短暂显示，不再遮挡任务与产物操作；
- 项目派发的任务已强制进入待验收，不再因 Runtime 成功退出而自动通过；真实 Codex 项目任务已完成项目→任务中心→项目时间线回流验证。

### U4：智能体管理与协作

1. 建立智能体卡片：图标、名称、颜色、角色、绑定 Runtime、位置、健康状态和默认工作区。
2. 将“默认 Profile”降级为兼容配置，不再作为智能体管理主界面；名称和图标由 Agent 元数据驱动。
3. 项目中选择协调者、执行者、测试者、审查者和验收者；协调者可以是 Hermes、Codex、OpenClaw、Claude Code 或人工。
4. 使用摘要、资源引用和产物引用交接上下文；由用户确认创建或派发任务。

验收：用户无需进入旧 Profile 页即可管理所有已接入智能体；每个项目都能明确看到协作分工与交接记录。

当前进展（2026-07-16）：

- “智能体”主界面已从旧档案表改为所有 Runtime 的统一卡片，覆盖 Hermes、Codex、OpenClaw、Claude Code；
- 卡片展示名称、类型、本地/远程位置、健康状态和启用状态，并提供对话、接入管理及本地外观编辑；
- 进入智能体页后自动执行轻量健康探测，探测期间显示“检测中”，刷新操作同步更新智能体列表与健康状态；
- 名称、颜色和头像仅写入桌面端显示元数据，远程服务配置保持不变；旧 Hermes 本地档案保留在默认折叠的兼容区；
- 项目页既有的项目经理、实施、测试、复核和验收分工继续作为唯一的项目职责来源。

### U5：真实使用打磨与发布门槛

1. 对 Hermes、OpenClaw、Codex、Claude Code 各执行连续对话、附件/项目目录、创建任务、任务完成、验收和重启恢复测试。

3. 收集一周真实使用中的高频路径，按“阻断、误导、操作次数”排序修复；不为低频功能增加主界面复杂度。
4. 完成 Windows 开发模式与打包版回归，确认普通用户权限运行即可。

验收：完成一项真实多智能体项目时，用户只需在对话、项目和任务中心三个界面之间工作；无 P0/P1 数据丢失、安全泄露或布局阻断。

## 5. 迁移原则

- **直接复用概念，不复制实现**：吸收 Multica 的看板、活动流、任务分配、协作组和计划任务模型；以 Agents One 自身数据结构和组件实现。
- **先做纵向闭环**：每轮都交付可见界面和真实 Runtime 测试，不再先堆完整底层能力再集中补 UI。
- **保持轻量**：不新增常驻服务、数据库、Docker 或后台 daemon；本地 Electron 数据层与现有 Bridge 是唯一控制面。
- **兼容优先**：现有 Hermes 对话、Runtime 设置、任务和缓存都可读取；新界面稳定后再逐步隐藏旧入口。
- **可验收优先**：每一轮必须有桌面截图、自动化交互和一次真实智能体任务的验收记录。

## 6. 建议的启动顺序

先实施 U0 和 U1，再立即交付 U2 的统一对话工作台。这样会先消除最明显的“旧 Hermes Desktop 外观”，同时让您每日使用的对话体验马上变得一致。项目、任务和协作能力随后进入 U3、U4；它们已有可用的数据基础，不需要推倒重写。

# Agents One 变更安全守则

本守则将“最小化修改、先评估后变更、可回退验证”固化为 Agents One 的开发门禁，避免一次局部优化破坏已接入智能体、历史记录或用户配置。

## 适用范围

任何 UI、交互、Runtime、项目/任务、对话、附件、持久化或构建改动都应遵循本守则。涉及智能体注册、`desktop.json`、会话历史、项目归属、头像名称映射、IPC 与 CLI 启动参数的改动，视为高风险变更。

## 一、先划定变更边界

开始编码前，先写出本次改动的目标、允许修改的模块和明确不应触碰的模块。UI 问题默认只在 Renderer 层处理；只有 UI 无法满足需求时，才能向 preload、main 或持久化层扩展。

| 请求类型               | 默认允许范围                   | 默认禁止触碰                               |
| ---------------------- | ------------------------------ | ------------------------------------------ |
| 布局、样式、文案、图标 | 目标 React 组件及其样式        | Runtime 注册、配置写入、迁移、会话同步     |
| 输入控件复用           | Renderer 组件、显示状态        | CLI 启动参数、工作区持久化、智能体基础配置 |
| 智能体接入或配置       | 对应 Runtime、设置页、配置读写 | 无关 Runtime、历史批量重写                 |
| 历史/项目数据修复      | 对应数据适配与迁移             | 删除原始数据、覆盖未知配置字段             |

## 二、高风险变更的事前评估

当必须修改受保护边界时，在代码变更前记录以下内容，可写进任务说明、PR 描述或进展日志：

1. 改动原因：为什么不能在更小的层级解决。
2. 影响数据：涉及哪些配置键、Runtime id、会话字段、项目归属或本地文件。
3. 下游消费者：哪些页面、IPC、任务执行器或历史恢复逻辑会读取这些数据。
4. 失败模式：配置丢失、Runtime 消失、头像名称回退、历史不完整、执行不可达等。
5. 回退方案：保留原值、原子写入与备份、可禁用开关或可单独回滚的提交。
6. 验证清单：自动化用例、开发版重启、受影响智能体和历史记录的人工冒烟路径。

没有以上评估，不进行跨层重构，也不顺手清理相邻模块。

## 三、持久化与用户数据保护

用户的 Runtime 配置、头像、名称、项目、会话和本地缓存属于不可随意改写的数据。

- 写 `desktop.json` 或同类配置前先读取现有内容，仅更新本次拥有的键，并保留未知键。
- 配置迁移必须幂等、可重复执行且不删除原始记录；无法识别的数据先保留并标记，不伪造用户消息或替换历史。
- Runtime 外观与 Runtime 执行配置分离：外观缺失不能让 Runtime 不可用，配置缺失不能抹除历史展示。
- 任何批量重建、清理或迁移前，先创建可恢复备份，并验证恢复路径。
- 新增默认 Runtime 不能覆盖用户同类 Runtime；禁用、编辑、删除语义必须明确并有测试。

## 四、分步实施与验证

每次变更遵守“一个假设，一个小补丁，一轮验证”的节奏。

1. 先添加或调整最贴近问题的测试，复现原问题或保护既有行为。
2. 只修改解决该问题所需的最少文件。
3. 先运行定向测试与类型检查，再启动开发版。
4. 重启后检查受影响页面，并额外检查同层的已接入智能体、项目/任务列表与历史记录。
5. 只有当前补丁通过，才处理下一项 UI 或功能优化。

不得把布局重构、Runtime 配置变更、数据迁移和品牌资源替换混在一个不可拆分的补丁中。

## 五、最小验收矩阵

| 变更范围           | 必做自动验证                                     | 必做人工验证                                  |
| ------------------ | ------------------------------------------------ | --------------------------------------------- |
| 纯 Renderer UI     | 目标组件测试、`npm.cmd run typecheck`            | 目标页面、窄窗口/侧栏状态、未受影响的同类页面 |
| Runtime 设置或接入 | Runtime/设置页测试、类型检查、目标 Runtime probe | 保存后重启、名称头像、可编辑性、一次真实对话  |
| 会话/项目持久化    | 持久化与映射测试、类型检查                       | 重启前后列表、用户消息与智能体回复、项目归属  |
| CLI 执行流程       | 事件解析测试、类型检查                           | 真实 CLI 任务、取消/超时、工具过程与最终答复  |

## 六、交付记录

每个关键修复完成后，立即更新 `docs/AGENTS_ONE_PROGRESS_LOG.md`，至少记录：问题、根因、改动边界、验证结果、已知风险和下一步。PowerMem 可用时同步高价值经验，但本地文档始终是可审计的项目事实来源。

## 本守则的由来

2026-07-23 的输入栏布局统一曾不当地牵连 Runtime 默认注册与外观解析，导致 Pi Agent 可用性、用户头像/名称和设置页编辑性出现回归。该事件说明：视觉一致性不能以破坏用户数据和既有功能为代价；后续必须先隔离层级，再以最小补丁推进。

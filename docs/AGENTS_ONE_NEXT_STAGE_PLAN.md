# Agents One 后续推进方案

更新日期：2026-07-30

## 目标

在不破坏既有智能体配置、项目、任务与对话记录的前提下，将 Agents One 从“基础能力齐备”推进到“界面一致、远程接入统一、数据可恢复、可发布”的稳定版本。

产品边界保持不变：任务对话优先；项目是任务对话的容器；本地 CLI 保留其原生能力；远程智能体逐步统一至 Agents One Remote Gateway v1。

## 执行原则

1. 每阶段只处理一个明确目标，完成回归和人工验收后再进入下一阶段。
2. 纯界面改动不得改写 Runtime 注册、凭据、项目关系或消息持久化结构。
3. 迁移远程智能体时保留原 `runtimeId`、显示名称、头像、历史任务和旧连接配置；禁止删除后重建。
4. 每次涉及数据模型、配置或迁移的改动，先完成本地快照、影响评估、回滚路径和自动化测试。
5. Release 前不再以“顺手重构”为名扩大改动面。

## Phase 0：安全基线

### 工作项

- 提交当前已验证代码，建立清晰的集成基线。
- 输出当前桌面数据清单：Runtime 定义、受保护凭据引用、项目、任务、对话、协作记录和产物索引。
- 建立四条黄金回归：远程 Hermes、OpenClaw、本地 Codex CLI、Hers Gateway v1。
- 为后续迁移准备紧急快照，不包含明文 Token。

### 验收

- 基线可在新目录构建。
- 四类 Runtime 均可打开历史任务、创建新任务、保存用户与智能体消息。
- 任一后续阶段失败时，可回到本阶段代码与数据快照。

## Phase 1：统一任务对话界面

### 工作项

- 抽取共享的 `ConversationShell`：标签页、任务标题、头像、消息流、输入区、附件、项目上下文、权限、侧栏和运行状态统一布局。
- 将 Hermes Dashboard、Gateway v1、Codex CLI、Claude Code CLI、Pi CLI 的事件映射为统一展示模型。
- 保留 Runtime 原生信息：CLI 的工具调用、思考摘要、命令/文件结果；远程 Gateway 的 Run、SSE/轮询、Artifact 与 Workspace Grant 状态。
- 统一空状态、错误状态、超时、取消和重试的中文文案。

### 约束

- 本阶段不得修改 Runtime ID、凭据读写、项目归属或对话存储。
- 仅新增展示适配层与截图回归；不要将不同 Runtime 的传输逻辑合并为一个实现。

### 验收

- Hermes、OpenClaw、Codex CLI、Hers 在同一窗口尺寸下具有一致的头部、消息区域、输入工具栏和侧栏位置。
- 每个 Runtime 仍能展示其特有的工具/思考/产物细节。
- 四类 Runtime 的连续对话、附件和项目文件夹上下文回归通过。

## Phase 2：Hermes 与 OpenClaw 迁移至 Gateway v1

### 工作项

- 远程 Hermes 和 OpenClaw 分别部署 Gateway v1 Adapter，对桌面端只暴露一个 `gatewayUrl` 与一个 Gateway Token。
- Adapter 内部兼容现有 Hermes API/Dashboard 与 OpenClaw Bridge/Workspace Gateway；桌面端不再保存多地址、多 Token。
- 提供“兼容模式 / Gateway v1”并行配置、能力探测、单项迁移和一键回退。
- 保留旧连接配置为只读兼容记录，直到真实回归完全通过。

### 验收

- 每个远程智能体仅用一个地址和一个 Token 完成 capabilities、连续对话、任务运行、取消、Artifact、超时恢复和 Workspace Grant。
- 迁移不改变 `runtimeId`，原头像、名称、任务、项目和历史对话均可继续访问。
- Hers 的 Gateway v1 真实读写验收继续作为远程工作区基准用例。

## Phase 3：任务与项目归档

### 工作项

- 使用软归档：任务和项目仅写入 `archivedAt`/归档状态，不移动、不删除底层消息、产物或关联。
- 提供已归档任务、已归档项目的筛选、搜索、恢复和只读浏览。
- 项目归档只影响可见性；恢复后保持原有任务顺序、Runtime、头像、项目上下文和产物链接。

### 验收

- 归档与恢复不丢失任何用户消息、智能体消息、协作时间线或附件索引。
- 已归档项目不再出现在默认列表，但可被搜索和完整恢复。

## Phase 4：客户端备份与恢复

### 工作项

- 实现手动备份、可选定期备份、保留策略、清单与 SHA-256 校验。
- 备份包含项目、任务、对话、协作、产物索引、Runtime 显示配置及应用设置；默认排除明文 Token/API Key。
- 实现恢复前预检、版本迁移、冲突提示、恢复前自动快照和失败回滚。
- 在全新用户数据目录执行真实恢复演练。

### 验收

- 从备份恢复后，项目层级、任务排序、消息、头像、名称和产物索引一致。
- 受保护凭据不会被明文导出；需要重新授权时给出明确提示。

## Phase 5：发布前调试与体验收口

### 工作项

- 执行数据持久化、升级、重启、离线、断连、取消、超时、失败恢复和删除确认回归。
- 执行 Gateway Token 脱敏、日志脱敏、路径穿越、符号链接、哈希冲突和 Workspace Grant 越权测试。
- 进行高 DPI、窄窗口、中文文本、空状态和错误状态的视觉验收。
- 清理隐藏或不可用的遗留入口，完成用户运行手册与故障诊断说明。

### 发布门槛

- 无 P0/P1 数据丢失或安全问题。
- 四类 Runtime 真实端到端回归全部通过。
- Hermes/OpenClaw Gateway v1 迁移完成且可回退。
- 归档与备份恢复演练通过。
- Windows 普通用户环境下开发启动和生产构建均通过。

## 当前 Hers 验证结论

2026-07-30 的独立端到端脚本 Run `run_229c17e43e3b4c71a03b986808db3b27` 已完成真实 `list=1`、`read=1`、`write=1`，在授权目录生成 `agents-one-gateway-e2e.txt` 并校验 SHA-256，随后主动撤销 Grant。

同日的新建任务复测确认了一个桌面端适配差异：Hers Relay 在 `pull` 响应中使用服务端生成的 `requestId`，而桌面轮询器此前仅读取 `id`，造成结果回传的 `requestId` 为空，Relay 无法关联结果并最终超时。桌面端已补充只读兼容映射：优先采用 v1 标准 `id`，仅在其缺失时采用同一服务端值 `requestId`；两者同时存在且不一致时拒绝请求。该变更不生成、不改写请求 ID，也不放宽路径或操作权限。已新增自动化覆盖；需重启桌面应用后再用新任务复测真实链路。
